# Serial Studio · 浏览器串口解析 / 发送工具

单文件、离线可用的串口调试工具，用 **Web Serial API** 在浏览器里收发数据，内置自动切帧、字段解析、CRC 校验、实时波形、快捷指令与可拖拽布局。

- 主程序：[`serial-studio.html`](./serial-studio.html)（双击即可运行，无需安装、无需联网）
- 逻辑自检：[`selftest/_selftest.py`](./selftest/_selftest.py)（在 Node 中真实执行页面脚本，64 项断言）
- 界面自检：[`selftest/_probe_layout.py`](./selftest/_probe_layout.py) / [`selftest/_probe_restore.py`](./selftest/_probe_restore.py) / [`selftest/_probe_banner.py`](./selftest/_probe_banner.py)（真实浏览器里模拟拖拽、启动恢复、无帧告警）

## 打开方式

| 方式 | 说明 |
| --- | --- |
| 双击 `serial-studio.html` | 直接以 `file://` 打开，无需服务器（推荐） |
| `msedge --app=file:///<路径>/serial-studio.html` | 以独立窗口打开，像本地应用 |
| 本地 HTTP 服务 | 需 `https` 或 `localhost` 才允许访问串口 |

在地址后加 `#demo`（如 `serial-studio.html#demo`）可直接进入**演示模式**，不接硬件就能看解析、波形和发送效果。

> ⚠️ 只有 **Chromium 内核**浏览器（Chrome / Edge 89+）支持 Web Serial；Firefox / Safari 下按钮会自动禁用，但仍可用演示模式。

## 四步上手

1. **连接**：选波特率 → 点「🔌 选择串口并连接」→ 在弹出的系统窗口里选设备。`DTR / RTS / 脉冲复位` 可用于复位 Arduino 等开发板。
2. **切帧**：在「② 帧解析器」选择切帧方式（原始流 / 按行 / 分隔符 / 定长长度字段 / 空闲超时）。
3. **解析**：在「③ 字段解析」按字节偏移定义字段，勾选「校验和验证」选择 CRC 算法。
4. **收发**：中间看报文与波形，右侧输入内容发送（支持文本 / HEX / 循环发送 / 快捷指令）。

## 切帧方式

| 方式 | 适用场景 | 关键参数 |
| --- | --- | --- |
| 原始流 | 只想看数据流、自行观察 | — |
| 按行 | `T=25.5,H=60\r\n` 之类的文本协议 | 行分隔符（LF / CRLF / CR / 任意） |
| 分隔符 | `AA 55 ... 0D 0A` 之类的二进制帧 | 帧头 HEX、帧尾 HEX（可只填其一） |
| 定长 / 长度字段 | 带 LEN 字节的二进制帧 | 帧头、长度位置、长度字节数、长度含义、附加值、端序 |
| 空闲超时 | 无长度无结尾、靠间隔分帧 | 超时毫秒数 |

长度字段的两种约定：

- 帧 = `AA 55 | LEN | 数据 | CRC16`，**LEN = 整帧字节数** → 选「整帧总长」，附加值 `0`
- LEN **只表示数据域长度** → 选「数据域长度」，附加值填尾部字节数（如 CRC 2 字节就填 `2`）

## 字段类型与校验

- 类型：`UINT8/16/32`、`INT8/16/32`、`FLOAT32/64`、`BITS`、`HEX`、`ASCII`、`BCD`，可单独指定端序
- 偏移从帧首字节算起；文本行协议把类型设为 `ASCII` 即可
- 校验算法：`CRC-16/MODBUS`、`CRC-16/CCITT-FALSE`、`CRC-16/XMODEM`、`CRC-16/IBM(ARC)`、`CRC-16/KERMIT`、`CRC-8`、`SUM8`、`XOR8`、`LRC`
- 校验范围：整帧（帧头 → 校验位前）/ 帧头之后 / 跳过首尾各 2 字节；校验位置支持帧尾或长度字段之后，端序可选

解析出的数值字段会**自动进入右侧波形**并计入 CSV 导出。

## 演示模式的内置协议

点「▶ 演示模式」后按 100 Hz 产生如下 22 字节帧，与本页默认解析配置完全对齐：

```
AA 55 | LEN=22 | 温度 f32 | 湿度 f32 | 电压 f32 | 电流 f32 | SEQ u8 | CRC16(LE)
 0   1     2      3..6       7..10      11..14      15..18     19       20..21
```

- 字段偏移：温度 3、湿度 7、电压 11、电流 15、SEQ 19（大端浮点）
- 校验：`CRC-16/MODBUS`，范围 = 整帧（帧头也计入），小端存放
- 参考值：SEQ=7、温度=25.5 时的完整帧为 `AA 55 16 41 CC 00 00 42 5D 00 00 41 43 33 33 3F 86 66 66 07 F5 83`

「示例：传感器」按钮会一键载入这套配置，可直接对照修改成自己的协议。

## 界面布局（可拖拽）

- **左右分栏**：拖动栏目之间的竖直分隔条（左/右各一条）调整三栏宽度，指针变宽时会高亮为青色
- **日志 / 波形**：拖动日志与实时波形之间的水平分隔条调整两者高度
- **双击任一分隔条**：恢复该处的默认尺寸（左 326 / 右 346 / 波形 250）
- 尺寸会写入 `localStorage`（键 `serial-studio-layout`），下次打开自动还原；窗口过窄时（≤1180px）自动切为上下堆叠布局并禁用左右拖拽，保证中间栏最小可用宽度

## 收不到数据时怎么查

界面已经内置了几层保护与提示，按下面顺序看即可快速定位：

1. **顶栏 `RX —` 指示灯**：只要有字节到达就会闪一下并显示原始 HEX。它不受切帧方式、过滤、暂停影响。
   - **它会闪** → 串口收数据正常，问题在解析配置（帧头/长度/波特率不匹配），点下面的「一键排查」即可看到原始字节。
   - **它始终不闪** → 串口层没收到数据，见第 4 步。
2. **「收不到数据？一键排查」按钮**：一键切到「原始流直显 + 只显示接收 + 无过滤 + 流控置无」，排除界面设置干扰。
3. **收到数据但切不出帧时的自动诊断**：只要累计收到 ≥256 字节却一帧都没切出来，日志区上方会弹出橙色横幅，它会
   - 自动**猜测帧头**（找重复出现且间距稳定的 2 字节模式，并给出重复次数与帧长）
   - 提供「按 `xx xx` 帧头切换」一键应用、「切到原始流直显」、「复制原始 HEX」、「关闭」
   - 同时打印前 96 字节原始 HEX，方便直接对着协议手册核对

   这是实际使用中最常见的情形：设备发的是自定义二进制帧，而默认帧头 `AA 55` 不匹配，字节会被当作噪声丢弃
   （此时左侧「错误 / 丢弃」计数会不断增大，而「帧数」保持 0）。
4. **8 秒零字节自动提示**：连接后 8 秒仍为 0 字节，日志里会给出排查清单（波特率、接线、切帧方式、流控）。
5. **串口层排查**：
   - 波特率必须与设备一致（支持手动输入非标准值）；数据位/停止位/校验也要匹配
   - TX↔RX 需要交叉连接；USB 转串口模块请确认是 TTL 电平而非 RS232
   - 连接时会主动置位 **DTR/RTS**（有些 CH340/CP2102 在 DTR 为低时根本不发数据）；若板子被持续复位，点 `DTR`/`RTS` 按钮取消
   - 「流控」若非「无」，而设备不支持 RTS/CTS，读取会一直阻塞 → 改回「无」
   - 若读取流被取消或拔插，程序会自动退避重试（最多 20 次），无需手动重连
   - 发送端已加 5 秒超时，对方不取数据时不会让界面假死
6. **控制台辅助**：`window.__rawHex(512)` 取最近收到的原始 HEX，`window.__analyzeHead()` 查看帧头分析结果。

## 上位机二进制帧协议配置（示例）

以 `SOF A5 | LEN | SEQ | CMD | DATA(LEN) | CRC8`（小端）为例，工具里的对应关系如下 —— 点「③ 字段解析」里的
**「示例：TLV 帧」**按钮可一键套用：

| 协议要素 | 工具设置项 | 取值 | 说明 |
| --- | --- | --- | --- |
| `SOF = 0xA5` | 帧解析器 → 帧头 HEX | `A5` | 单字节帧头 |
| `LEN` 紧跟 SOF | 长度字段位置 | `1` | **帧内偏移**：SOF=0、LEN=1 |
| `LEN` 占 1 字节 | 长度字节数 | `1` | |
| `LEN` = DATA 字节数 | 长度含义 | `数据域长度（不含头尾）` | |
| 整帧 = SOF+LEN+DATA+SEQ+CMD+CRC | 长度附加值 (+) | `3` | 公式 `整帧 = 长度字段位置(1) + 长度字节数(1) + LEN + 3`，3 = SEQ+CMD+CRC8 |
| CRC 覆盖 LEN~DATA | 校验算法 | `CRC-8 (poly 0x31, init 0xFF)` | 多项式 0x31、初值 0xFF、无反射 |
| CRC 不含 SOF | 校验范围 | `帧头之后（LEN → 校验位前）` | |
| CRC8 在帧尾 | 校验字节位置 / 校验值端序 | `帧尾` / 小端 | 单字节时端序无影响 |
| 字段偏移 | SEQ=2、CMD=3、DATA=4（长度填 `0` = 自动延伸到 CRC 之前） | | 帧首为偏移 0 |

参考帧（可直接粘到「发送」区用 HEX 模式回环验证）：

```
LEN=0 → A5 00 01 01 8E
LEN=2 → A5 02 02 10 01 02 31
LEN=8 → A5 08 03 20 00 01 02 03 04 05 06 07 03
```

日志会显示为 `SEQ=2  CMD=16  DATA=01 02  ✓ 校验通过`。

> 「长度附加值」的语义是 `整帧 = 长度字段位置 + 长度字节数 + LEN值 + 附加值`。
> 若 LEN 表示**整帧长度**（长度含义选「整帧总长」），附加值一般填 `0`。

## 已知限制

- 长度字段切帧**不能自我重同步**：若数据流从帧中间开始（中途插拔、先前丢过字节），
  数据里偶然出现的帧头字节会让解析器按错误长度等待。点「清空」重新开始即可对齐。
- **校验失败不会触发重同步**：数据里的假帧头若恰好与 CRC 碰撞，会导致切出"看起来合法"的错帧，
  风险大于收益，因此不作自动重同步。校验结果会标在每行末尾与「最新解析结果」中，便于人工核对。
- 长度字段位置一律按**帧内偏移**理解（帧首 = 0），与「字段解析」表里的偏移含义一致。

## 其他功能

- 报文格式：`HEX + 文本` / 仅 HEX / 仅文本 / 仅十进制，可切换方向、按文本或 `/正则/` 过滤
- 日志导出：TXT（原始收发记录）、CSV（数值字段时间序列）
- 快捷指令：一行一条，支持 HEX 解析，改动自动存入浏览器本地
- 配置保存 / 恢复：波特率、切帧、字段、校验等一键持久化
- 快捷键：`Enter` 发送 · `Ctrl+Enter` 换行 · `Ctrl+K` 清空 · `Ctrl+L` 聚焦发送框

## 自检

```bat
python selftest\_selftest.py       :: 逻辑：切帧 / CRC / 字段 / 编码 / 接收链路诊断（64 项）
python selftest\_probe_layout.py   :: 界面：真实浏览器里模拟拖拽分隔条（10 项）
python selftest\_probe_restore.py  :: 界面：记忆尺寸在启动时正确恢复（5 项）
python selftest\_probe_banner.py   :: 界面：无帧告警横幅渲染（产出截图）
```

`_selftest.py` 会抽取页面内联脚本、用最小 DOM 桩在 Node 中执行，并校验：HEX 解析、CRC 标准向量、字段解析、逐字节粘包 / 随机分片 / 前导噪声下的切帧、行切帧、空闲超时切帧、CRC 篡改检测、发送编码、演示模式端到端、接收链路诊断（原始流不丢字节、零字节看门狗、帧头自动识别与无帧检测）。

`_probe_layout.py` / `_probe_restore.py` / `_probe_banner.py` 会基于页面生成临时副本并在 headless Edge 中打开，用 `PointerEvent` 模拟拖拽，校验拖拽 1:1 跟手、双击复位、`localStorage` 持久化、重开页面后尺寸恢复、无横向溢出，以及注入「帧头不匹配」数据后告警横幅是否正确弹出。

除截图脚本外，其余全部通过时退出码为 0。需要 Node.js 与 Edge/Chrome；可用环境变量覆盖路径：`set NODE_EXE=...`、`set BROWSER_EXE=...`。
